## Why this test follows Phase 2K-B

Phase 2K-B answered the cheapest open question from the Phase 2K-A backlog: once the
63-session volatility / beta / correlation risk premium is regressed out, does any
candidate feature still rank a *residual* forward return? The answer was a qualified
yes — neutralization removed the failed 63d risk-premium tilt, and a short list of
features cleared the IC floor against the residual label with a stable yearly sign.
Phase 2K-B flagged those as `KEEP_FOR_ROBUSTNESS_TEST` and explicitly routed the
next step here.

But a surviving rank IC on a ~40-name, single-regime 2023–2026 export is a **lead,
not an edge** — exactly the kind of apparent signal that Phase 2I-B's overlap-aware
bootstrap, permutation null, and leave-one-out checks already demolished once (it
dropped all six Phase 2I-A survivors, which fed the Phase 2J-A `NO_GO`). Phase 2K-C
holds the residual candidates to the same bar before any of them earns the right to
walk-forward model research. The question is sharp: **does any residual candidate
survive out-of-sample-style stress, or is it a small-sample / single-regime
artifact?**

## Which residual candidates were tested

The candidates are read at run time from the Phase 2K-B output —
`keep_drop.keep_for_robustness_test` — so this phase always validates exactly the
shortlist Phase 2K-B produced, each at the best horizon Phase 2K-B raised it on
(`features[<name>].best_horizon_days`). No candidate is hard-coded here; if the
upstream shortlist changes, the tested set follows. `candidates_tested` in the
output records the resolved list.

## How the residual label is rebuilt

This phase does **not** re-implement residualization — it imports the Phase 2K-B
analyzer and calls its `build_forward_labels`, `build_panel`, and
`residualize_label` functions, so the residual labels here are byte-for-byte the
same construction Phase 2K-B raised the candidates on. Importing the module only
binds its functions and constants; it runs nothing, so Phase 2K-B is **not executed
as a side effect**.

For each forward horizon (5 / 10 / 21 / 63 sessions):

1. **Forward excess label** — forward return is `adj_close` shifted `-h` within each
   ticker; SPY's forward return over the same horizon is subtracted.
2. **Cross-sectional neutralization** — on each `as_of_date` the forward excess
   label is regressed across names on the trailing risk controls
   (`rolling_beta_63d`, `realized_vol_21d`, `realized_vol_63d`, `downside_vol_21d`,
   `rolling_corr_spy_63d`) plus an intercept via OLS (`numpy.linalg.lstsq`; no
   scipy); the residual is the beta/vol-neutralized label.
3. **Robust fallback** — when a date has no usable control or fewer than
   `min_names_for_ols` usable names, the residual falls back to a cross-sectional
   demean. Per-date OLS-vs-fallback counts are recorded in
   `residualization_config.fit_counts`.

**Leakage is avoided** exactly as in Phase 2K-B: the controls are strictly trailing
point-in-time features, the label is strictly forward, and each per-date fit mixes
only same-date cross-sectional information — never future or cross-date data.

## How robustness is tested

For each candidate, at its best Phase 2K-B horizon (with a per-horizon residual-IC
summary attached for context), the analyzer runs the Phase 2I-B battery against the
residual label:

- **Stability** — yearly and quarterly residual rank IC, a rolling 6-month IC view,
  sign stability by year and quarter, and top-minus-bottom spread plus top-decile
  residual hit rate by year, each with its sample size.
- **Bootstrap CI** — a moving-block bootstrap (1000 resamples) for the mean residual
  rank IC, with **block length = the horizon**, so heavily overlapping 21d / 63d
  forward windows are resampled in contiguous blocks rather than as if independent.
  `excludes_zero` is the honest significance read.
- **Permutation null** — a two-sided sign-flip permutation test (1000 permutations)
  for H0: the per-date residual IC is centered at zero.
- **Leave-one-year-out** — re-mean the IC dropping each calendar year; the sign must
  hold every time to be called stable.
- **Leave-one-ticker-out** — drop the dominant long-leg name and re-measure, to see
  whether the edge depends on a single ticker.
- **Concentration** — per-ticker share of the top residual quintile (long leg), the
  top contributors, and an `overly_concentrated` flag when the top-3 share exceeds
  0.50.
- **Regime tests** — residual IC in SPY-up vs SPY-down forward windows, in high vs
  low market volatility, and in high vs low cross-sectional feature dispersion; a
  sign flip across the SPY up/down split marks the candidate regime-dependent.

### The conservative recommendation rule

Each candidate gets one recommendation —
`KEEP_FOR_MODEL_RESEARCH` / `KEEP_AS_RESEARCH_LEAD_ONLY` / `DROP` /
`NEED_MORE_DATA` — under a deliberately strict gate. A candidate may be
`KEEP_FOR_MODEL_RESEARCH` **only if all** of the following hold: the bootstrap CI
excludes zero, the permutation null is significant, the leave-one-year-out sign is
stable, the long leg is not overly concentrated, the edge is not regime-dependent,
and there are enough effective (overlap-discounted) observations
(`n_dates / horizon ≥ min_effective_obs`). Otherwise it is `NEED_MORE_DATA` (sample
too thin), `DROP` (significance fails), or `KEEP_AS_RESEARCH_LEAD_ONLY` (significant
but concentrated or regime-dependent). Even `KEEP_FOR_MODEL_RESEARCH` is **not**
permission to train or deploy a model — it only allows the next research phase to
scope walk-forward validation.

## Whether any candidate survives

This is computed from the data at run time and recorded in the JSON; validate it
against the emitted artifact rather than assuming it. The relevant fields are
`recommendation_summary.counts`, `interpretation.any_candidate_survives_robustness`,
`interpretation.edge_concentrated_in_few_tickers`, and
`interpretation.edge_regime_dependent`. The recommended next phase is derived from
those counts:

- **At least one `KEEP_FOR_MODEL_RESEARCH`** → `recommended_next_phase` = **2L-A —
  Walk-Forward Residual Model Research Design** (scope an out-of-sample,
  walk-forward validation design for the surviving residual signal(s); still no
  model candidate until that passes).
- **Only `KEEP_AS_RESEARCH_LEAD_ONLY`** → **2K-D — Extend Data / Broaden Universe
  Before Model Research** (the lead is concentrated or regime-dependent; acquire
  longer history and a broader point-in-time universe to retest it out of a single
  regime).
- **All `DROP` / `NEED_MORE_DATA`** → **2K-D — Alpha Data Acquisition for New
  Hypothesis Families** (no residual alpha to model; move to data acquisition for
  the remaining Phase 2K-A families).

## Why no model candidate is created yet

The Phase 2K-A model-candidate gate is still locked, and this phase respects it:
no model candidate may be created until a feature family passes out-of-sample
robustness across more than one market regime. A single moving-block bootstrap and
a permutation test on overlapping windows from one bull regime are necessary but not
sufficient — they screen out noise, they do not prove an edge will hold out of
sample. The strongest verdict this phase can issue, `KEEP_FOR_MODEL_RESEARCH`, only
authorizes *designing* a walk-forward validation (Phase 2L-A); it does not fit,
score, promote, or deploy anything. This phase therefore stops at measurement and a
recommendation, and it asserts no **production edge**.

## Conclusion

Phase 2K-C is the robustness gate between a residual *lead* and residual model
*research*. It rebuilds the Phase 2K-B residual labels exactly, subjects each
surviving candidate to an overlap-aware bootstrap, a permutation null, leave-one-out
stability, concentration, and regime splits, and issues a conservative
recommendation that — at most — authorizes designing walk-forward validation, never
training or deployment. It keeps the research platform, rejects unvalidated signal,
creates no model candidate, and claims no **production edge**.
