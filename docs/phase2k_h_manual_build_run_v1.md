# Phase 2K-H — Manual Free Expanded Dataset Build Run (v1)

_Tracked by `research/analyze_phase2k_h_manual_build_run.py` and validated by
`tests/test_phase2k_h_manual_build_run.py`. Phase 2K-H is the **manual** free expanded dataset
build run. The analyzer here is a read-only tracking artifact: it inspects the D: drive build
outputs AFTER the user runs the build, summarizes them, and writes one small Git-tracked
summary JSON. It does **not** run the build, fetch any data, train a model, or claim a
**production edge**._

> Scope: this phase is a manual data build plus a read-only tracking artifact. It is research
> tooling only: it **does not deploy**, it **does not restart stock-api.service**, it
> **does not enable** the model-v2 serving flag, it **does not run migrations**, it
> **does not write to production DB**, and it **does not trade**. No order placement, no
> automation, no model training, no model candidate, and no live build is run by the analyzer
> or the tests, and it claims no **production edge**.

## Why Phase 2K-H follows Phase 2K-G

Phase 2K-G implemented the import-safe free expanded dataset builder and proved it works using
only safe dry-run and fixture modes, recommending **Phase 2K-H — Manual Free Expanded Dataset
Build Run**. Phase 2K-G deliberately did **not** run the full live build: fetching ~8–10 years
of free daily adjusted OHLCV for a broad universe is a heavier, network-bound step that the
user runs **manually and separately**. Phase 2K-H is that manual run, plus a small read-only
analyzer that records what the run produced so the project can decide whether the expanded
dataset is ready for the survivorship-aware residual-signal retest (Phase 2K-I).

## The manual build command (run separately by the user)

The build itself is **not** run by this analyzer or the tests. The user assembles the full
local ticker universe on the D: data root, then runs the Phase 2K-G builder manually in its
explicit network build mode (Windows PowerShell only):

```powershell
python research/build_phase2k_g_free_expanded_dataset.py --execute --allow-network `
  --data-root "D:\Stock_Prediction_app_data\phase2k_g" `
  --universe "D:\Stock_Prediction_app_data\phase2k_g\input\phase2k_g_free_universe_tickers.csv" `
  --start 2016-01-01 --end 2026-01-01
```

This fetches the free daily adjusted OHLCV + volume, assembles the survivorship-caveated panel,
runs the data-quality checks and pass/fail gates, and writes the five real outputs into
`D:\Stock_Prediction_app_data\phase2k_g\output`. Even then it **does not deploy**, **does not
enable** the model-v2 flag, **does not write to production DB**, **does not run migrations**,
**does not trade**, and claims no **production edge**.

## D: drive storage policy

Large expanded datasets, cache files, and the real build outputs live **outside** the C: repo,
on the dedicated data drive rooted at `D:\Stock_Prediction_app_data\phase2k_g`:

- real outputs → `D:\Stock_Prediction_app_data\phase2k_g\output\`
- retrieval cache → `D:\Stock_Prediction_app_data\phase2k_g\cache\`
- the full (non-sample) ticker universe → `D:\Stock_Prediction_app_data\phase2k_g\input\phase2k_g_free_universe_tickers.csv`

The C: repo keeps only lightweight, source-controlled files: the analyzer, the tests, this doc,
and the small summary JSON. This analyzer is **read-only** with respect to the D: data files —
it reads the JSON summaries and streams the CSV headers / row counts, and never rewrites,
moves, or deletes anything on the D: drive.

## Expected outputs (read after the manual run)

The manual build writes five files under `D:\Stock_Prediction_app_data\phase2k_g\output`:

- `phase2k_g_expanded_price_history_free.csv` — the longer, broader daily adjusted OHLCV + volume panel.
- `phase2k_g_expanded_scored_free.csv` — the feature-ready / scored panel derived from the price history.
- `phase2k_g_data_quality_report.json` — the data-quality report with `PASS` / `PASS_WITH_CAVEAT` / `FAIL` status.
- `phase2k_g_data_build_summary.json` — reproducible run metadata and safety flags.
- `phase2k_g_survivorship_caveat.json` — explicit survivorship-caveat metadata.

## What the analyzer validates after the manual run

The analyzer is fast and lightweight. It:

- detects which of the five expected D: outputs exist;
- reads the data-quality report, build summary, and survivorship caveat JSONs;
- streams the two CSVs for header and row count only (it does not load the full expanded
  CSVs into memory);
- confirms no large outputs leaked into the C: repo;
- writes one small summary JSON (`research/output/phase2k_h_manual_build_run_summary.json`)
  carrying the data root, expected vs. detected outputs, the three summaries, CSV metadata, a
  decision block, the recommended next phase, and the machine-readable safety flags.

## What happens if the outputs are missing

If one or more of the five expected outputs is absent, the analyzer records
`decision.manual_build_detected = false` and `decision.ready_for_retest = false`, sets
`recommended_next_phase.phase = "2K-H-RUN"`, and clearly explains that the manual build has not
been completed yet. Nothing is fetched and nothing is written to the D: drive — the user simply
runs the manual build command above and re-runs the analyzer.

## What happens if the outputs pass

If all five outputs exist, the data-quality status is `PASS` or `PASS_WITH_CAVEAT`, the
survivorship caveat confirms `point_in_time_membership_claimed = false`, and the build summary
confirms no model candidate was created, the analyzer records
`decision.manual_build_detected = true`, `decision.ready_for_retest = true`, and sets
`recommended_next_phase.phase = "2K-I"` with title
**"Expanded Dataset Residual Signal Retest"**. The expanded panel is then ready to retest the
liquidity candidate `avg_dollar_volume_21d`, with every result reported as survivorship-biased.

## When a manual run must be treated as failed

The first manual `--execute` run exited 0 but produced `rows=0 dq=FAIL`: the free retrieval
returned unexpected column shapes per ticker, every ticker was skipped, and an empty dataset
was nearly mistaken for a good build. The analyzer correctly recorded
`manual_build_detected = true`, `data_quality_status = FAIL`, `ready_for_retest = false`, and
routed back to **2K-H-RUN**. The Phase 2K-G builder has since been hardened so this cannot be
silently mistaken for `BUILD_OK`:

- **A live build is failed when `row_count == 0` or `data_quality_status == FAIL`.** In that
  case the builder still writes the five outputs for inspection but marks the summary
  `build_ok = false` and **exits non-zero**, so PowerShell never treats it as `BUILD_OK`.
- **Individual ticker failures are allowed, but must be reported.** A failed or empty ticker
  does not abort the run; it is recorded in the build summary's `retrieval_diagnostics`
  (`failed_tickers`, `empty_tickers`, plus requested/successful/rows counts) and printed to
  stdout.
- **A successful command must create non-empty data with `PASS` or `PASS_WITH_CAVEAT`.** Only
  then is the run a real build, and only then does this analyzer route forward to 2K-I.
- **Large outputs remain on `D:\Stock_Prediction_app_data\phase2k_g`** in every case, never in
  the C: repo.

Re-run the hardened manual build command above, then re-run this analyzer; once the run
produces non-empty data that is `PASS` / `PASS_WITH_CAVEAT`, the analyzer routes to 2K-I. This
phase still **does not deploy**, **does not restart stock-api.service**, **does not enable** the
model-v2 flag, **does not run migrations**, **does not write to production DB**, **does not
trade**, and claims no **production edge**.

## Why no model candidate is created yet

This phase produces and tracks data, not models. The Phase 2K-A model-candidate gate stays
locked: no model candidate may be created until a feature family passes the IC sweep and the
out-of-sample robustness / walk-forward battery on real data spanning more than one market
regime, with no single-regime artifact, no excessive ticker concentration, and no look-ahead
leakage. The manual 2K-H build produces the multi-regime panel; evaluating it is the later
Phase 2K-I retest. Phase 2K-H trains nothing, fits nothing, and creates no model candidate.
The model-v2 serving flag stays disabled.
