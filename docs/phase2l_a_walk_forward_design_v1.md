## Why this phase follows Phase 2K-C

Phase 2K-C ran the Phase 2I-B robustness battery (moving-block bootstrap with block
length = horizon, sign-flip permutation null, leave-one-year-out, leave-one-ticker-
out, concentration, and market-regime splits) against the Phase 2K-B residual
candidates. Under a deliberately strict gate, exactly one candidate —
`avg_dollar_volume_21d`, at its 63-session horizon — cleared every condition and was
labelled `KEEP_FOR_MODEL_RESEARCH`. Two others (`excess_return_vs_spy_63d`,
`return_63d`) remained research leads only, and `momentum_12_1` was dropped. Phase
2K-C routed the next step here.

Phase 2K-C was explicit that clearing its gate is **not** a **production edge** and
**not** permission to train or serve a model — it only earns the right to *design*
an out-of-sample, walk-forward validation protocol. This phase produces exactly that
design and nothing more.

## Why `avg_dollar_volume_21d` is only a research candidate

`avg_dollar_volume_21d` survived robustness on a single-regime, ~40-name, 2023–2026
export. A moving-block bootstrap and a permutation test on heavily overlapping 63d
windows from one bull regime are necessary screens, not proof that an edge holds out
of sample. The signal is also a liquidity proxy — exactly the kind of feature that
can ride a regime rather than express durable cross-sectional alpha. So it is a
candidate to *validate walk-forward*, not a model and not an edge. This phase fits
nothing and creates no model candidate; it asserts no **production edge**.

## The walk-forward design

- **Target label.** The same beta/vol-neutralized residual forward return used in
  Phase 2K-B / 2K-C — forward excess-vs-SPY return neutralized per date against the
  trailing risk controls. Phase 2L-B reconstructs it identically (no relabeling).
- **Candidate signal.** `avg_dollar_volume_21d`, ranked cross-sectionally.
- **Primary horizon.** 63 sessions, from the Phase 2K-C / 2K-B candidate horizon.
  Optional comparison horizons are **21d and 63d only**.
- **Training windows.** Two options are specified: an **expanding-window** (anchored
  start, span grows each fold) and a **rolling-window** (fixed trailing span that
  slides forward) so non-stationarity / decay can be detected.
- **Validation windows.** Strictly sequential time splits. The validation period is
  **always chronologically after** the training period, there is **no overlap**
  between training-label and validation-label windows, and there is **no random
  cross-validation**.
- **Embargo.** An embargo **equal to the forward horizon** (63 sessions) is dropped
  between the last training label and the first validation label.

## Embargo and leakage controls

Because the 63d forward labels overlap, a training label that ends inside the
validation window would peek across the boundary; the horizon-length embargo removes
that overlap. The full leakage controls are:

1. **Trailing-only features** — the candidate signal and every residualization
   control are trailing point-in-time values; none uses forward data.
2. **Point-in-time universe** — names are included only if they were members as of
   each date; no survivorship or forward-membership injection. If the universe is
   later broadened, membership stays resolved point-in-time per date — today's
   membership is never back-applied to historical dates.
3. **Train-only residualization fit** — the residualization is fit only from
   training / same-date cross-section information; no validation-window information
   enters any fit. The label is strictly forward; each per-date fit mixes only
   same-date data.
4. **Embargo** — horizon-length gap between train and validation labels.
5. **No validation-set threshold tuning** — gate thresholds are fixed in advance
   (inherited from Phase 2I-A / 2K-B / 2K-C) and never tuned on validation results.

## Model-free baseline first

Phase 2L-B validates a **model-free, rank-only** strategy on the single feature
**before any model is considered**. Names are ranked each date by
`avg_dollar_volume_21d`; the long/short direction is fixed from the training window
and applied unchanged to validation; nothing is fitted. Per validation window it
measures the residual-label rank IC, the top-minus-bottom residual spread, the
top-decile residual hit rate, a turnover / stability proxy, and long-leg ticker
concentration, then aggregates the distribution across folds so no single fold can
carry the result.

The **walk-forward pass/fail gates** are: validation mean residual IC positive and
above the inherited floor; a majority of validation windows share the training sign;
a moving-block bootstrap CI of the pooled validation IC excludes zero; no single
validation window drives the result; no excessive ticker concentration; no
regime-only dependence; no degradation versus the Phase 2K-C result; no look-ahead
leakage; and enough effective observations after the embargo.

## Why no model candidate is created yet

The Phase 2K-A model-candidate gate stays locked. Clearing Phase 2K-C's robustness
gate authorizes *designing* walk-forward validation (this phase) and then running
the *model-free* baseline (Phase 2L-B) — not fitting, scoring, serving, or promoting
anything. A later, separately gated phase may consider a **single-feature monotonic
model or rank transform only** (no multi-feature model, no neural network, no
complex ML, no production scoring, no serving integration, no model-v2 enablement),
and only if the model-free baseline passes. This phase authorizes none of it and
creates no model candidate. It asserts no **production edge**.

## What Phase 2L-B will do

Phase 2L-B implements the **model-free walk-forward validation** designed here: it
reconstructs the residual label, derives the concrete sequential folds with the
horizon-length embargo from the session calendar, computes the rank-only metrics on
each out-of-sample validation window, aggregates and bootstraps the pooled
validation IC, and records an explicit PASS/FAIL per gate. Phase 2L-B trains no
model, fits nothing, serves nothing, and creates no model candidate.
