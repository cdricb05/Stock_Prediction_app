## What dataset will be built later

A single long-format daily panel keyed on `(date, ticker)` with adjusted OHLCV plus volume,
derived `dollar_volume`, and an aligned benchmark close:

- **History:** minimum **8 years**, recommended **10 years** of daily bars, spanning more
  than one market regime (up, down, high/low volatility, and at least one sustained
  drawdown).
- **Universe:** a broad liquid U.S. equity set (S&P 500-style), at least **100 tickers per
  date**.
- **Columns:** `date, ticker, adjusted_open, adjusted_high, adjusted_low, adjusted_close,
  volume, dollar_volume, benchmark_close`.

This is the multi-regime panel the Phase 2K-B → 2K-C → 2L residual-signal battery needs;
the current ~3.4-year, ~41-name export cannot satisfy it.

## Why this phase does not build or download data

The mandate is a plan, not the build. Separating the plan from the build keeps each step
auditable and keeps the safety surface small: this phase makes no network call, fetches no
data, downloads nothing, acquires no paid data, and creates none of the future files. The
build script, the ticker universe file, the data fetch, and the dataset are all deferred to
Phase 2K-G. The decision block records `create_build_script_now = false`,
`execute_data_build_now = false`, `download_data_now = false`,
`acquire_paid_data_now = false`, and `create_model_candidate_now = false`.

## Target universe and survivorship caveat

The free build uses a **current-as-of** liquid universe as a free approximation of
membership. Because true point-in-time constituent history and clean delisted-name coverage
are paid-leaning (per Phase 2K-E), the plan carries an **explicit survivorship caveat**:

- membership is documented as current-as-of, **not** point-in-time;
- no false point-in-time membership claim is made;
- any retest run on the panel must be reported as **survivorship-biased**, never as a clean
  point-in-time result;
- a strictly clean point-in-time build is **deferred** to a later paid-source decision.

The ticker universe file is a **local / manual** file — never a network source — with
columns `ticker, name, sector, source, active_as_of, survivorship_caveat`. A
current-membership list is acceptable **only** with this caveat recorded.

## Planned future script (declared, not created here)

`research/build_phase2k_g_free_expanded_dataset.py` would read the local universe file and
run parameters; retrieve free daily adjusted OHLCV + volume per ticker in chunks (with retry
/ backoff and a local cache); assemble the panel and derive dollar-volume + benchmark
alignment; run the data-quality checks; and write the five output files with idempotent,
reproducible output and explicit run metadata. By design it **must not** write to any
database, integrate with the live service, score or serve any model, create orders or
automation, acquire any paid data, or claim point-in-time membership.

## Data-quality gates

The future build must run, at minimum: adjusted-close continuity; duplicate `(date,
ticker)` detection; missing adjusted-close / volume below threshold; outlier daily returns;
no zero/negative prices; zero/negative volume only where expected; ticker-level date
coverage; benchmark coverage; minimum-years and minimum-ticker-count achieved; no
forward-filled labels; no point-in-time membership claim; and survivorship-caveat present.
These carry the Phase 2K-E preflight gates forward. The **pass/fail gates** then require all
required files created, ≥8 years, ≥100 tickers, complete-enough benchmark coverage, zero
duplicate rate, missing critical fields below threshold, the survivorship-caveat file
present, and `data_quality_report.status` in PASS / PASS_WITH_CAVEAT / FAIL.

## Why no model candidate is created yet

This phase only plans data. The Phase 2K-A model-candidate gate stays locked: no model
candidate may be created until a feature family passes the IC sweep and the out-of-sample
robustness / walk-forward battery on real data spanning more than one market regime, with no
single-regime artifact, no excessive ticker concentration, and no look-ahead leakage. That
multi-regime panel does not exist yet — building it (cleanly enough, with the survivorship
caveat) is precisely what 2K-G is for. Phase 2K-F trains nothing, fits nothing, builds no
dataset, and creates no model candidate. The model-v2 serving flag stays disabled. No
**production edge** is claimed.
