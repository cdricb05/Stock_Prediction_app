_Generated by `research/analyze_phase2k_e_data_feasibility.py`. This is a feasibility
artifact, not a data build and not a model. It reads the Phase 2K-D data-expansion plan
plus the Phase 2L-B / 2K-A summaries and the Phase 2G run summary, inventories the data
already on disk, and assesses whether the expanded dataset Phase 2K-D requires can be
assembled locally / free / low-cost before any residual-signal retest. It acquires no
data, downloads nothing, buys no paid data, trains nothing, fits nothing, creates no
model candidate, and claims no **production edge**._

## Why Phase 2K-E follows Phase 2K-D

Phase 2L-B could not advance the surviving residual candidate `avg_dollar_volume_21d` to
model research on the current ~40-name, single-regime 2023–2026 export. Phase 2K-D turned
that result into a disciplined data-expansion plan — longer history, a broader
point-in-time universe, survivorship controls, the target validation capacity, the
data-quality / leakage gates, and the acquisition options — and set
`continue_model_research_now = false` and `create_model_candidate_now = false`. Phase
2K-D explicitly routed here: **before** spending effort assembling that dataset (let
alone buying it), verify whether it can plausibly be built locally / free / low-cost at
all. Phase 2K-E answers exactly that and decides whether a paid point-in-time dataset is
warranted now.

## What local data exists today

The feasibility analyzer inventories `research/output/` by path. The existing Phase 2G
free end-of-day export is present: a daily price-history CSV and a scored CSV, plus the
Phase 2G-C run summary. From the run summary the current panel is roughly three years of
daily bars (~2023 → 2026) across ~40 mega-cap names, with the benchmark series and volume
already present. That is the same thin, single-regime panel that Phase 2L-B could not
validate on, so the inventory records `satisfies_2kd_target_capacity = false`: the current
data is far short of the 8–10 year, ≥100-name, multi-regime target.

## Which Phase 2K-D requirements are feasible with current / free data

The price/volume inputs needed to retest the liquidity candidate are feasible on the free
path:

- **Longer price history** — `FEASIBLE_WITH_FREE_EXTENSION`. The existing free
  end-of-day source can be pulled further back for listed names toward 8–10 years.
- **Broader equity universe** — `FEASIBLE_WITH_FREE_EXTENSION`. A materially broader
  *current* ticker list (toward the full liquid S&P 500) is free to request.
- **Liquidity / volume history** — `FEASIBLE_WITH_FREE_EXTENSION`. Volume is already in
  the export and extends with the same free source; dollar-volume is derivable.
- **Benchmark / factor data** — `FEASIBLE_NOW`. The benchmark series is already present
  and deep free history is readily available.
- **Sector / industry classification** — `FEASIBLE_WITH_FREE_EXTENSION` (and not required
  to retest the liquidity candidate). A current free snapshot is a usable approximation.

## Which requirements are blocked

Two requirements are the only paid-leaning gaps, and both are flagged
`REQUIRES_PAID_POINT_IN_TIME_DATA`:

- **Point-in-time universe membership** — clean as-of-date constituent history is the
  scarce piece; a naive current-membership list back-applied to the past is survivorship
  biased and not admissible without an explicit caveat.
- **Survivorship-bias controls** — free end-of-day sources typically drop delisted /
  merged names, so the free path cannot fully cover names over their live span.

Point-in-time fundamentals and analyst estimates are also paid-leaning, but they are
**future-phase**: they are not required to retest a price/volume liquidity feature and
only later, different hypotheses would need them.

## Does paid point-in-time data appear required now?

**No — not for a first retest.** Because `avg_dollar_volume_21d` is a price/volume
liquidity feature, every *required* input except clean point-in-time membership and
survivorship coverage is feasible free. Phase 2K-D already sanctioned the fallback: if
true point-in-time membership cannot be sourced, the dataset must carry an **explicit
survivorship caveat** and the retest must report its results as survivorship-biased
rather than treating them as clean. The feasibility decision therefore records:

- `can_build_expanded_dataset_without_paid_data = true` (a survivorship-caveated free
  build of longer adjusted OHLCV across a broader current universe is assemblable),
- `can_retest_avg_dollar_volume_without_paid_data = true` (with that caveat),
- `paid_data_required_now = false` — a paid point-in-time + survivorship dataset is the
  soundest basis and is **reserved for a later clean confirmation**, not bought now,
- `proceed_to_data_build = true`,
- `clean_build_requires_paid_point_in_time_data = true` — a strictly clean (non-caveated)
  build would still need paid point-in-time data.

## What the next phase should do

`recommended_next_phase` routes to **Phase 2K-F**. Because the free route can plausibly
retest the candidate under a survivorship caveat, the recommended 2K-F is the **Free
Expanded Price/Volume Dataset Build Plan**: design a local / free data-build script plan
for longer daily adjusted OHLCV and a broader universe, carrying the explicit survivorship
caveat, with the data-quality preflight checks, so the Phase 2K-B → 2K-C → 2L-A / 2L-B
battery can be re-run on a multi-regime panel. (If clean membership gaps had instead
blocked any meaningful retest, 2K-F would instead be a **Point-in-Time Universe Source
Decision** comparing free / low-cost / paid options before any build.) Either way, 2K-F
acquires no paid data, trains no model, and creates no model candidate.

The `data_quality_preflight_plan` carries the Phase 2K-D data-quality gates forward as
checks the build phase must pass on the assembled dataset before any retest — adjusted-
close consistency, split / dividend sanity, missing-date handling, ticker continuity,
delisting / survivorship treatment, duplicate detection, no forward-filled labels, no
look-ahead membership — plus an assertion that a survivorship caveat is documented when
point-in-time membership is not sourced.

## Why no model candidate is created yet

This phase only checks data feasibility. The Phase 2K-A model-candidate gate stays locked:
no model candidate may be created until a feature family passes the IC sweep and the
out-of-sample robustness / walk-forward battery on real data spanning more than one market
regime, with no single-regime artifact, no excessive ticker concentration, and no
look-ahead leakage. Phase 2K-E trains nothing, fits nothing, builds no dataset, and
creates no model candidate. The model-v2 serving flag stays disabled. No **production
edge** is claimed.
