## Why this test follows Phase 2K-A

Phase 2I-A swept thirteen point-in-time features against forward excess-vs-SPY
return and found that the only KEEP survivors were a 63-session
volatility / beta / correlation cluster. Phase 2I-B stress-tested those six
survivors and dropped every one; Phase 2J-A locked the result into a `NO_GO`
(`promote_model_v2 = false`, `build_phase2j_model_candidate = false`) because the
sole measurable edge was a regime-dependent **risk premium**, not market-neutral
alpha. Phase 2K-A turned that into a ranked backlog whose cheapest, highest-priority,
testable-now hypothesis is `beta_vol_neutralized_residual_signal` — and explicitly
recommended Phase 2K-B as the next step.

This phase runs exactly that hypothesis on data we already trust. The question is
sharp: **once the volatility/beta/correlation risk premium is regressed out, does
any candidate feature still rank a residual forward return?** If yes, we have a
new lead to validate; if no, we have cheaply confirmed that current data holds no
market-neutral alpha and the next move is data acquisition, not modeling.

## How the residual labels are constructed

For each forward horizon (5 / 10 / 21 / 63 sessions):

1. **Forward excess label.** From local price history, forward return is
   `adj_close` shifted `-h` within each ticker; SPY's forward return over the same
   horizon is subtracted to form the forward excess-vs-SPY label. (The 5-session
   price-derived excess was confirmed identical to the scored label in Phase 2I-A,
   so all four horizons are derived uniformly here.)
2. **Cross-sectional neutralization.** On each `as_of_date`, the forward excess
   label is regressed across names on the trailing risk controls —
   `rolling_beta_63d`, `realized_vol_21d`, `realized_vol_63d`, `downside_vol_21d`,
   `rolling_corr_spy_63d` — plus an intercept, via ordinary least squares
   (`numpy.linalg.lstsq`; no scipy). The **residual** of that regression is the
   beta/vol-neutralized label: the part of the forward excess return that the risk
   controls do not explain.
3. **Robust fallback.** When a date has no usable control (all-NaN or constant) or
   fewer than `min_names_for_ols` usable names, the residual falls back to a
   cross-sectional demean (subtract the per-date mean of the label). The per-date
   counts of OLS vs fallback dates are recorded in
   `residualization_config.fit_counts`.

The Phase 2I-A rank-IC machinery — per-date Spearman rank IC, information ratio,
yearly / quarterly IC, top-minus-bottom quintile spread, top-decile residual hit
rate, sign stability by year, and the low-confidence sample guard — is then run
unchanged against this residual label, so the residual results are directly
comparable to the original 2I-A raw-excess results.

## How leakage is avoided

- **Controls are strictly trailing.** Beta, realized vol, downside vol, and SPY
  correlation are point-in-time features computed as of the row's `as_of_date`;
  none uses any forward data.
- **The label is strictly forward**, and the per-date OLS fit mixes only same-date
  cross-sectional information — never future dates.
- **No imputation of the future.** Names missing a usable control on a date are
  excluded from that date's regression rather than back-filled, so no forward or
  cross-date information leaks into the residual.
- **Thresholds are inherited from Phase 2I-A** (`rank_ic_floor = 0.03`,
  `year_sign_min = 3`, `min_dates = 120`, `min_names_per_date = 5`) so nothing is
  tuned to flatter this phase.

## Does the failed 63d risk-premium edge disappear after neutralization?

The risk controls regressed out are exactly the Phase 2I-A KEEP cluster. By
construction, testing those same controls against the residual label should drive
their rank IC toward zero. The analyzer reports this in
`comparison_to_phase2i_a.control_features_ic_collapse` (raw vs residual best
`|IC|` per control) and sets
`comparison_to_phase2i_a.neutralization_removed_63d_risk_premium = true` when **no**
control still clears the `0.03` IC floor on the residual label. The
`interpretation.beta_vol_neutralization_eliminates_63d_signal` flag mirrors that
verdict. This is computed from the data at run time — validate it against the
emitted JSON rather than assuming it.

## Does any residual alpha candidate survive?

Each candidate feature (`return_5d/10d/21d/63d`, `momentum_12_1`,
`excess_return_vs_spy_21d/63d`, `volume_zscore_21d`, `avg_dollar_volume_21d`) is
scored against the residual label and given one recommendation:

- **`KEEP_FOR_ROBUSTNESS_TEST`** — clears the IC floor at its best horizon with a
  year-stable sign and a sufficient sample.
- **`NEED_MORE_DATA`** — best horizon is sample-guarded (low confidence).
- **`DROP`** — confident but below the floor or sign-unstable.
- **`CONTROL_ONLY`** — the trailing risk controls, which are neutralized out and so
  are never treated as alpha candidates.

`interpretation.any_residual_alpha_candidate_survives` and
`keep_drop.keep_for_robustness_test` record the answer. If a candidate survives,
`recommended_next_phase` routes to **2K-C — Residual Alpha Robustness Validation**
(run the Phase 2I-B robustness battery on the survivor). If none survives,
it routes to **2K-D — Alpha Data Acquisition for New Hypothesis Families**
(longer history / broader universe / point-in-time fundamentals), explicitly
*not* model training.

## Why no model candidate is created yet

A surviving residual rank IC on a ~40-name, single-regime 2023-2026 export is a
**lead, not an edge**. Phase 2I-A already produced apparent survivors that Phase
2I-B's overlap-aware bootstrap, permutation null, and leave-one-year-out / 
leave-one-ticker-out checks demolished. The Phase 2K-A model-candidate gate
remains locked: no model candidate may be created until a feature family passes
that out-of-sample robustness battery across more than one market regime. This
phase therefore stops at measurement and a recommendation; it does not fit, score,
or promote anything, and it asserts no **production edge**.
